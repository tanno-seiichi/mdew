# mdew 設計メモ（開発者向け）

mde の画面を HTML で作り直したアプリケーションです。この文書は、mdew の作りと、できることの一覧を開発者向けに
まとめたものです（使い方は、リポジトリの直下の `README.md` を参照してください）。

## フォルダ構成

- `mdew.sln`：ソリューション（`mdew\mdew.csproj` と `msi\msi.wixproj` の2つのプロジェクト）
- `README.md`：ユーザーズガイド（初めて使う方向けの使い方）。インストーラーにも同梱します
- `LICENSE.txt`：mdew のライセンス（MIT）
- `doc\DESIGN.md`：この文書（開発者向けの設計メモ）
- `doc\TODO.md`：作業予定（mde にできて mdew でまだできないこと、確認が残っているもの、対応済みのこと）
- `mdew\`：アプリ本体のプロジェクト
  - `mdew.csproj` / `Program.cs` / `AppSettings.cs`：WebView2 を載せる入れ物（WPF）。
    ファイルを開く・保存する、画像の保存など、OS とのやり取りを担当します（ari 版と同じもの）。
    64bit（x64）専用です（`RuntimeIdentifier` を `win-x64` にしているので、WebView2Loader.dll は x64 用だけが
    実行フォルダの直下にコピーされます）。
  - `dialog\AboutWindow.xaml`：バージョン情報のウィンドウ（mde から移植）
  - `dialog\FindReplaceWindow.xaml`：検索と置換のウィンドウ（mde から移植。検索・置換の処理は `web\js\find.js`）
  - `dialog\DialogStyles.xaml`：ダイアログの部品（ボタン・入力欄・チェックボックス等）の Windows 11 風の見た目（メッセージボックスとそろえる。検索と置換・リンク・表を挿入・PDF の余白で使う）
  - `dialog\PdfMarginDialog.xaml`：PDF の余白の設定（mde から移植）
  - `dialog\TableSizeDialog.xaml`：右クリックの「表を挿入…」の行数・列数の指定（mde から移植）
  - `dialog\LinkInputDialog.xaml`：右クリックの「リンクにする…」の URL の入力（mde から移植）
  - `app.manifest`：アプリのマニフェスト（コモンコントロール 6 を使う設定。メッセージボックスを今の Windows の見た目で表示する）
  - `WebMenu.xaml`：メニューバーのメニュー（WPF のメニューで開く。Program.cs の ShowWebMenu）の見た目。
    右クリックのメニュー（HTML）とそろえてある
  - `images\mde.ico` / `images\mde.png`：アプリのアイコン（mde と同じもの）
  - `web\`：画面側。ビルドは不要で、ここのファイルがそのまま実行フォルダへコピーされます。
  - `index.html` / `app.css`：画面の構成と見た目
  - `js\main.js`：画面全体の動き、ホスト（C#）とのやり取り
  - `js\editor.js`：編集部分（入力時の書式変換、元に戻す、編集していない部分を元のまま保存する仕組み）
  - `js\markdown.js`：Markdown の読み込み・書き出し
  - `js\folder.js`：フォルダビュー
  - `js\find.js`：検索と置換
  - `js\clipboard.js`：Excel 等の他のアプリとのコピー・貼り付け（書式付きの HTML → Markdown の変換を含む）
- `msi\`：インストーラー（WiX Toolset 4）のプロジェクト（mde の msi を元にしたもの）
  - `Package.wxs`：製品名・バージョン・アップグレードコード・アイコン等
  - `Directory.wxs`：インストール先のフォルダ構成（`web\js` を含む）
  - `File.wxs`：同梱するファイルの一覧と、エクスプローラーの右クリックメニュー「mdew で開く」・スタートメニューへの登録。
    MSI はファイルを１つずつ列挙する必要があるため、`web\` にファイルを追加・削除した時や、
    NuGet のパッケージを追加・更新した時は、ここも直してください
  - `UpgradeConfirmDlg.wxs`：アップグレード時の確認・右クリックメニューを追加するかの確認の画面
  - `Package.ja-JP.wxl` / `Package.en-US.wxl`：画面の文言（日本語版・英語版の msi がそれぞれ作られます）
  - `License.rtf` / `LICENSE.txt`：インストール時に表示する・同梱するライセンス
  - `THIRD-PARTY-NOTICES.txt`：サードパーティ（WebView2 SDK）のライセンス表示。インストール先に同梱します。
    NuGet のパッケージを追加・更新した時は、この中のバージョン・ライセンス文も直してください

## ビルド

Visual Studio で `mdew.sln` を開いてビルドするだけです（Node.js は不要です）。

構成を Release にしてソリューションをビルドすると、インストーラーも作られます
（`msi\bin\x64\Release\ja-JP\mdew.msi` と `en-US\mdew.msi`）。インストーラーには mdew の実行フォルダ
（`mdew\bin\Release\net10.0-windows`）のファイルが入るので、先に mdew のビルドが通っている必要があります
（ソリューションのビルドでは、プロジェクトの参照により mdew が先にビルドされます）。

- 文字の書式：太字（Ctrl+B）・斜体（Ctrl+I）・下線（Ctrl+U）・取り消し線（Alt+Shift+5）・
  インラインコード（Ctrl+Shift+`）・ハイライト。右クリックのメニューからも使えます（表のセルの上では表の操作も）
- アウトラインは見出しの階層で折りたためます（▾／▸）。ステータスバーのボタンで、フォルダビュー・アウトラインの表示を切り替えられます
- 右クリックの「ページトップに戻る」・「リンクにする…」（選んだ文字をリンクにする）・「見出し」（見出しのレベルの変更）・「表を挿入…」（行数・列数を指定）・「ソースモードに切り替え」（mde と同じ）
- フォルダビュー（mde と同じ内容）：メニュー「ファイル」→「フォルダを開く...」で開いた時だけ、左端に表示します。
  - フォルダの中のサブフォルダと Markdown ファイル（.md・.markdown）の一覧。クリックでファイルを開きます
  - 保存していないファイルは名前の先頭に「* 」。別のファイルへ切り替えても変更は消えず、開き直すと戻ります。
    「ファイル」→「すべて保存」でまとめて保存します（閉じる時は、保存していない変更があれば確認します）
  - 上の「…」で別のフォルダを開き直せます。「表示」→「フォルダを表示」で隠せます
  - 起動時の引数にフォルダを指定した場合も、そのフォルダを開いて、直下の最初のファイルを開きます（mde と同じ）
- ソースモード（「表示」→「ソースモード」。mde と同じ）：Markdown のソースを直接編集します。
  切り替えた時は、カーソルと表示の位置を同じ段落などに合わせます。検索と置換・保存・ファイルの切り替えも使えます。
  終了時には覚えません（次回は Markdown モードで起動します）
- 検索と置換（Ctrl+F・メニューバーの「検索と置換」。mde と同じウィンドウで、メインのウィンドウの外へも動かせます）
  - 対象範囲：現在のファイル／フォルダ全体（サブフォルダ含む。フォルダを開いている時だけ）
  - 大文字・小文字を区別する、正規表現を使用する（置換後の文字列で $1 等が使えます）
  - 前を検索・次を検索・すべて検索（Enter）、置換後の文字列を開くと 1件ずつ置換…・すべて置換。Esc で閉じます
  - 結果の一覧はダブルクリックでその箇所へ移動します。閉じても入力した内容は残ります
  - フォルダ全体の置換は、保存するまでファイルには書き出しません（フォルダビューに「* 」が付きます）
- 「表示」のメニュー（Alt+V）：アウトラインを表示・ステータスバーを表示（表示中は ✓）、
  段落中の改行（ソースの通りに改行する／空行が入るまで改行しない。mde と同じ。既定は「空行が入るまで改行しない」）。
  次回起動時も同じ表示にします。
  「空行が入るまで改行しない」は表示だけの切り替えで、保存する内容は変わりません（改行のすぐ隣で文字を入力すると、
  その改行が空白に変わることがあります）
- 「ファイル」のメニュー（Alt+F）：新規（Ctrl+N）・開く（Ctrl+O）・保存（Ctrl+S）・名前を付けて保存（Ctrl+Shift+S）・
  閉じる（Ctrl+W。このウィンドウを閉じます）。新規は新しいウィンドウを開きます
- 最近使ったファイル（「ファイル」のメニューのサブメニュー。mde と同じ）：開いた・保存したファイルを、新しい順に 10 個までフルパスで表示します。

## 起動時間

起動を速くするため、次のようにしています（`Program.cs`）。

- ウィンドウは、画面の準備ができてから、中身ごと表示します（`MainWindow.StartHidden`・`RevealWindow`）。先に空のウィンドウを
  表示すると、中身が出るまでの間（WebView2 の起動・画面の読み込み）白いウィンドウが見えて、起動が遅く見えるためです（mde・Typora 等と
  同じ見え方）。ウィンドウは、まず画面の外に（タスクバーに出さず、アクティブにせずに）表示して、WebView2 の準備と画面の読み込みを
  進めます（WPF の WebView2 は、ウィンドウを表示するまで準備を始めないため、表示しないままにはできません）。画面側は、起動時の
  内容（起動時引数のファイル、または空の文書）を表示し終えると `revealed` をホストに送り、ホストはそれを受けて、ウィンドウを
  一度隠し、本来の位置に戻して表示し直します。前回終了時に最大化していた時は、この時に最大化します。準備が 4 秒
  （`REVEAL_TIMEOUT_MS`）を過ぎても終わらない時は、待たずに表示します。
- WebView2 の環境（裏で動く Edge のプロセス）は、ウィンドウを作る時に作り始めます（`MainWindow.CreateWebViewEnvironmentAsync`）。
- ブラウザのキャッシュは、web フォルダのファイル・mdew.dll が前回消した時から変わった時だけ消します（`WebCacheStamp`。
  前回の印は `%LocalAppData%\mdew\webcache.stamp`）。web フォルダのファイルを書き換えても、古いファイルが使われることはありません。
  印は、アプリのバージョンと、web フォルダのファイル・mdew.dll の一番新しい更新日時です。実行フォルダの場所は入れません
  （別名のドライブから同じフォルダの mdew を起動した時に、無駄に消さないため）。
  消すかどうかの確認（web フォルダのすべてのファイルの更新日時を調べる）は、ウィンドウを作る時に裏のスレッドで始め、
  WebView2 の準備と並行して進めます（`MainWindow.m_webCacheCheck`）。
- 最初の配色は、画面の URL（`index.html?theme=…`。theme のメッセージの JSON）で画面側に渡します。
  `AddScriptToExecuteOnDocumentCreatedAsync` で渡すと、登録が終わるのを待つのに 0.3〜0.9 秒かかることがあったためです。
- Release でビルドした時は、mdew.dll を ReadyToRun の形（あらかじめネイティブコードにコンパイルした形）にします
  （`mdew.csproj` の `ReadyToRunBuildOutput`）。起動時の JIT（実行時のコンパイル）が減ります。ReadyToRun は本来、発行（publish）の
  時だけ作られるので、ビルドの後に obj の中のフォルダへ発行して、できた mdew.dll で実行フォルダの mdew.dll を置き換えます
  （インストーラーは実行フォルダのファイルを同梱します）。最初のビルドの時は、ReadyToRun のコンパイラー等のパッケージを
  NuGet から取得します。使わない時は `-p:ReadyToRunBuild=false` を付けてビルドします。
- .NET のマルチコア JIT（`ProfileOptimization`）を使います。前回の起動でコンパイルしたメソッドを
  `%LocalAppData%\mdew\startup.jitprofile` に記録しておき、次回の起動では別のスレッドで先にコンパイルします（2 回目の起動から効きます）。

`mdew.csproj` の `TraceLog` を `true` にしてビルドすると（コンパイルスイッチ `TRACE_LOG`）、起動にかかった時間を、
起動のたびに `%LocalAppData%\mdew\error.log` に 1 行で記録します（`StartupTiming`。起動・終了の記録も書きます）。
時間は、どれもプロセスの開始からの時間です。既定は `false` で、error.log にはエラーだけを書きます（エラーが無ければ
error.log は作られません）。

```
起動時間：Main=80ms WebView2の環境=350ms WebView2の準備=520ms … 画面の準備=700ms ファイル表示=730ms 表示の指示=760ms ウィンドウ表示=800ms
```

| 名前 | 時点 |
|---|---|
| Main | .NET の起動が終わり、mdew の処理が始まった |
| WebView2の環境 | 裏で動く Edge のプロセスが起動した |
| WebView2の準備 | ウィンドウの中の WebView2 が使えるようになった |
| キャッシュの確認 | キャッシュを消すかどうかの確認が終わった（裏で先に終わっていれば「WebView2の準備」とほぼ同じ時間になる） |
| キャッシュ削除 | web フォルダのファイルが更新されていたので、キャッシュを消した（消さなかった時は出ない。消した理由は、別の行に「ブラウザのキャッシュを削除：…」と書く） |
| 画面の読み込みの指示 | WebView2 に画面（`web\index.html`）を読み込むよう指示した |
| 画面の読み込み開始 | 画面側が読み込みを始めた（ここから「main.js開始」までは画面側の時刻。`main.js` の `startupTiming`） |
| HTML | `index.html` を読み終えた |
| CSS | `app.css` を読み終えた |
| js | js のファイルをすべて読み終えた |
| main.js開始 | `main.js` の実行が始まった（読み込んだ js のファイルの実行が終わった） |
| 画面の準備の送信 | 画面側が準備を終えて、ready を送った（画面側の時刻） |
| 画面の準備 | 画面側（`web\index.html`・js）の準備ができた |
| ファイル表示 | 起動時引数のファイルを画面に表示した（開くファイルが無い時は「ファイル無し」） |
| 表示の指示 | 画面の準備ができたので、ウィンドウを本来の位置に表示する（準備を待ちきれずに表示した時は、別の行に「画面の準備を待たずに表示」と書く） |
| ウィンドウ表示 | ウィンドウを本来の位置に表示した |

起動時間は、ウィンドウを本来の位置に表示し、起動時の内容を表示し終えた時に記録します。

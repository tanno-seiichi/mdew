## 様子を見て検討するもの

- [ ] 保存する時に、開いた後でファイルが書き換えられていないかを確かめる（2026-10-15）
  - 同じファイルを2つのウィンドウで開けるため（「新規」で開いたウィンドウ等）、両方で編集して保存すると、後から
    保存した方で知らせなく上書きされ、先に保存した側の変更が消える。ほかのアプリでの書き換えも同じ
  - 案：開いた時（と保存した時）のファイルの更新日時・大きさを覚えておき、保存の前に変わっていたら
    「ほかで書き換えられています。上書きしますか？」と確認する（フォルダを開いている時の「すべて保存」も同じ）
  - 別の案：ほかのウィンドウで開いているファイルを開こうとしたら、そのウィンドウを前面に出す

- [x] **ウィンドウを閉じる時の確認を「…は変更されています。閉じる前に保存しますか？」（はい・いいえ・キャンセル）にする**（2026-10-18）
  - 確認のダイアログ（dialog\ConfirmDialog）：Windows のメッセージボックスと同じ見た目（白い部分に OS 標準の「？」のアイコン
    とメッセージ、下の灰色の帯にボタン）。既定（Enter）は「はい」、Esc はキャンセル
  - はい：保存してから閉じる（新規の文書は保存先を選ぶ。フォルダを開いている時に保存せずに置いておいたファイルも保存する）。
    保存先の選択をキャンセルした・保存に失敗した時は閉じない。いいえ：保存せずに閉じる
  - 保存する内容・ファイル名は HTML 側にあるため、閉じる時にいったん閉じるのをやめて HTML 側に問い合わせ（confirmClose）、
    返事が届いてから確認を出す（Program.cs の ConfirmClose）。画面が応答しない時は 3 秒後に「保存せずに閉じますか？」を出す

- [x] **本文の幅を、編集ペインの幅に合わせて広げられるようにする**（2026-10-18）

    表も本文の幅に合わせて広く表示される（main.js の setFullWidth、app.css の body.full-width。次回起動時に復元）
  - 「編集ペインの幅に合わせる」の時は、ウィンドウを狭くしても表が編集ペインの幅（余白を除く）に収まるよう、セルの中の

  - 同じく、セルの最小幅（3em）もなくす（列の多い表は、最小幅 × 列数が編集ペインの幅を超えて、はみ出していた）

  - mdew ではステータスバーではなく、メニュー「表示」に「表示倍率：○%」「拡大」（Ctrl++）「縮小」（Ctrl+-）
    「100%に戻す」（Ctrl+0）を置いた。Ctrl+マウスホイール（編集ペインの上）でも拡大・縮小する
  - mde と同じく 50%〜250%、10% ずつ。次回起動時に復元する（WebView2 の localStorage）。Markdown の表示は

- [x] **マウスのドラッグで範囲選択している途中で、選択が消えることがある**（2026-10-17）
  - 原因：ブラウザは、ブロックの間の余白（段落・見出し・リスト等の上下の margin）の位置を「次のブロックの先頭」と
    みなす。行の先頭から行の末尾より右へドラッグしている時に、マウスが少し上にずれて余白に入ると、選択の端が
    行の先頭（選択の始まりと同じ位置）に飛び、選択が消えたように見えていた
  - ドラッグ中にマウスが余白（編集領域・リスト・引用の余白）にある時は、選択の端を、上下でいちばん近い行の、
    マウスの横位置にする（editor.js の adjustDragFocus。ブラウザが選択を広げた後、描画の前に直す）

- [x] **入れ子の空の項目で Enter を押すと、リストの記号が2つ同じ行に並ぶ**（2026-10-16）
  - 原因：入れ子の空の項目で Enter（Shift+Tab も同じ）を押して1段上に戻ると、後ろの項目がその項目の入れ子になる
    （Markdown の決まり）。その時、項目自身の行が無いと「・ ◦ 見出し」のように記号が並び、
    カーソルも入れ子の項目（「見出し」）の先頭に置かれていた
  - 項目自身の行（<br>）を作り、カーソルをそこに置く（editor.js の ensureOwnLine・placeCaretAtStart。
    「-」だけの行の下に入れ子がある Markdown を開いた時も同じ。markdown.js の renderBlock）
  - その空の行で BackSpace：空の行を消して、後ろの項目を前の項目の入れ子に戻す（removeEmptyParentItem）
  - 追記：上記の後も、親の項目の文字を消した時等に同じ表示になった（ブラウザの編集で、<br> の無い空の項目ができる）。
    どの編集でできた場合でも直るよう、文書を変更するたびに、入れ子のリストだけを持つ空の項目に <br> を置くようにした
    （editor.js の ensureOwnLines。changed から呼ぶ。日本語の入力の途中では行わない）
  - 追記：ユーザーの操作は、入れ子のある項目の先頭で BackSpace だった（ブラウザ標準では文字だけが前の項目に移り、
    入れ子のリストを持つ空の項目が残る）。入れ子のある項目の先頭で BackSpace を押した時は、文字を見た目で1つ上の行
    （前の項目の中の最後の項目・入れ子の先頭なら親の項目）につなげ、入れ子の項目も前の項目の下へ移すようにした
    （Wordと同じ。editor.js の mergeIntoPreviousItem。最上位のリストの先頭の項目は段落に戻す）
  - あわせて、入れ子を持つ最上位の項目を段落に戻した時（Shift+Tab・空の項目で Enter）に、入れ子の項目が消えていた
    のを直した（段落の後ろにリストとして残す。outdent）
  - mde は、空の項目で Enter を押すとリスト全体から抜ける（後ろの項目は元のまま）ため、この問題は無い

- [x] **他のアプリの書式付きの内容を、Markdown にして貼り付ける**（2026-10-16）
  - Claude のアプリの返答をコピーして貼ると、箇条書きの記号が外れていた。Chromium の文字（text/plain）には
    リストの記号が入らず、これまでは HTML を表の時しか使っていなかったため
  - HTML を Markdown に直して貼る（clipboard.js の htmlToMarkdown）：箇条書き・番号付きリスト（入れ子・
    開始番号・チェックボックス）・見出し・太字・斜体・取り消し線・下線・マーカー・リンク・インラインコード・
    コードブロック（言語も）・引用・表・横線・画像（Web 上の画像はそのまま、Word 等の一時ファイルは一時フォルダへコピー）
  - Word のリスト（mso-list の段落）・Google ドキュメントの太字（span の font-weight）にも対応。文字の色等の飾りは捨てる
  - 見出し・リスト・リンク等のタグが無い HTML（ただの段落・VS Code のコードの色付け等）は、これまでどおり文字を貼る
  - 書式にできない場所（引用の中にリストを貼る等）と、表のセルの中に段落以外を貼る場合は、文字のまま貼る。
    Ctrl+Shift+V（書式なしで貼り付け）・Excel の表の貼り付けは、これまでどおり
